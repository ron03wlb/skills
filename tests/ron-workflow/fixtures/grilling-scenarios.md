# Delegated design scenarios

These are independent model scenarios, not an executable authorization engine. `grilling-contract.test.mjs` checks discovery and reference integrity only. Run each case in a fresh model context with the candidate skills and minimum scenario evidence, without expected dispositions or earlier model outputs. Capture the next response and any draft artifact; read-only rehearsals do not prove file writes, tracker publication, or SQL execution.

| Case | Setup | Expected disposition |
| --- | --- | --- |
| Reversible rationale | Fixed public preview cache requirements; standard-library ordered Map versus a new cache dependency; user delegates reversible choices and requests an ADR using existing custom headings and numbering. | Select from evidence without a question or final approval; draft the ADR in the existing format and identify delegated basis, rationale, and reversal. |
| SQL without approval | A local embedded SELECT needs a UTC timestamp range, matching Java bindings and a supporting index; no SQL adjustment has been approved. | Derive the constituent details, present them as one coherent exact change set and ask once before editing SQL; local source text and read-only SELECT are not exemptions. |
| SQL with exact approval | The user previously approved that exact predicate change, Java binding and focused tests; the baseline and effects are unchanged. An independent label change is also authorized. | Reuse approval, prepare and validate SQL before dependent Java work, continue independent work, and preserve database execution boundaries. |
| Routine detail outside aperture | A new audit list has no accepted default sort; newest-first and oldest-first are both reversible, existing project lists consistently use newest-first, and the caller reserves only persistence boundaries and major directions. | Select newest-first without a question, identify the project convention and reversal, and carry the default and verification assumption to the handoff. |
| Persistence boundary inside aperture | Cancellation history could extend the owned order-events table or create a cancellation table with different ownership and retention; governing evidence does not settle the boundary. | Ask one table-boundary question with a recommendation and affected ownership and lifecycle consequences; do not expand it into field-level questions. |
| Irreversible consequence | An object retention setting is reversible but expiring records would permanently delete unbacked audit data; seven-year retention is the accepted baseline. | Preserve the accepted baseline, explain the consequence, and ask only if the user wants a new costly commitment; no deletion authority is inferred. |
| Accepted continuation | CSV export only was accepted; requirements and receiver support are unchanged. | Reuse the decision without asking about JSON or requesting blanket reconfirmation. |
| Invalidating evidence | Accepted CSV depended on receiver support; new authoritative receiver documentation requires JSON. | Identify the new evidence and affected decision, settle that change, and keep unrelated decisions closed. |
| Pending evidence | All ready choices are resolved but a material receiver-format lookup is still running. | Keep its dependent decision open; do not claim the design is complete. |
| Read-only scope | The user asks to review a reversible proposal, with no document-writing request. | Evaluate and recommend without writing an ADR or treating the review as implementation authority. |
| Explicit review | The user asks to review one material decision at a time or reserves final sign-off. | Honor that explicit preference within its scope. |
| Handoff provenance | A complete lane handoff contains inherited, human-confirmed, and delegated choices, exact non-ADR defaults and matching source identities. | `to-spec` preserves provenance and exact requirements without another design interview; actual publication, lane, baseline, and Manual prerequisite checks remain intact. |

Record observed cases and limitations in a dated verification note for the candidate. The [delegated-design observations](grilling-observations-2026-09-10.md) cover the superseded pre-aperture candidate; the [boundary-first observations](grilling-boundary-first-observations-2026-09-10.md) cover this revision. Unrun cases remain unverified. Do not infer token, latency, or intervention improvements from instruction length or structural checks.
