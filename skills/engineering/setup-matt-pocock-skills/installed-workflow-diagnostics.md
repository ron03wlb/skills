# Installed workflow diagnostics

This is a read-only diagnostic contract for the workflow surfaces visible to the current harness and repository. It never authorizes or denies publication, execution, integration, aggregate verification, or push. Every later skill must read its own authority again at its mutation boundary.

A required seam that reads `MISSING` or `UNKNOWN` leaves readiness not-ready, with the seam's owning source and its smallest human action named. Readiness is never claimed from a probe set that cannot detect the failure class the selected substrate actually exhibits.

Resolve installed paths from the current harness's available-skill inventory or configured skill root. Do not treat a source checkout, a cached summary, or a similarly named file as installation proof. Do not create, copy, link, repair, or promote a missing skill or adapter during diagnostics.

## Re-derived bootstrap criteria

Readiness here is re-derived against the substrate [ADR-0080](../../../docs/adr/0080-deliver-issue-lanes-through-native-subagent-lanes.md) selects, not carried over from the retired `pi-workflow` materialization. Every criterion names the prerequisite it depends on; a prerequisite is kept only while its own probe can detect the failure class the criterion names, and one that cannot is retired or replaced instead ([Former prerequisites, re-derived](#former-prerequisites-re-derived)).

| # | Re-derived criterion | Prerequisite it depends on | Owning source that proves or repairs it | Read-only proof |
| --- | --- | --- | --- | --- |
| R-1 | Complete preflight before approval: the repository, tracker, labels, package, managed entries, bindings and every required seam read their own state before any mutation | One row of `## Required observations` per seam, with the installed package version bound to the entry set the environment actually resolves, plus the publication capability the configured tracker needs | Each seam's own row; the installation owner for the environment-resolved entries; `scripts/github-producer-transport.mjs` in the installed coordinator for the GitHub capability probe | The seam rows' states and the probe's recorded capability observation; unreadable or contradictory evidence stops with its owning source named. |
| R-2 | One bounded plan and one explicit acceptance: setup presents the resolved plan once and performs no mutation before one explicit human acceptance | The resolved plan inventory, readable from its owning sources | This skill, under [ADR-0072](../../../docs/adr/0072-make-setup-an-approved-operational-bootstrap.md) as amended by [ADR-0079](../../../docs/adr/0079-amend-the-setup-bootstrap-for-the-pi-workflow-substrate.md) | The accepted plan is the plan the owners executed; a changed source, target, binding, external effect or recovery action has a new acceptance, and an unchanged accepted operation is never re-asked. |
| R-3 | Owner sequencing: the accepted owners run in dependency order and every receipt is read back | The owner's own read-back surface, named by the seam's row and by the owner's interface reference | The existing owners of repository configuration, create-only labels, installation (`scripts/workflow-installation.mjs` in the installed coordinator), managed entries, producer bindings and tracker effects | The owner's receipt. Setup never reproduces package building, installation, binding, tracker mutation, recovery or receipt logic (ADR-0059). |
| R-4 | Truthful readiness: `READY` only from verified receipts and `PRESENT` seams, otherwise one attributable not-ready verdict | Each required seam's own verdict, never a re-derivation of it | The owner named by that seam's row; for lane settlement, the selected substrate read through `scripts/lane-settlement-capability.mjs` in the installed coordinator | The seam state plus `## Truthful readiness reduction`; lane settlement is `READY` only from that probe's `PROVEN` verdict. |
| R-5 | Boundaries: setup never replaces its own running bytes, creates or closes product Issues, starts or grants a product Run, pushes, deploys, or performs database work | None measured: these boundaries are decided and only observed | ADR-0072, ADR-0079, and ADR-0040's sole Start authority | Setup reports a seam; it neither repairs another owner's seam nor claims that owner's verdict as its own. |

## Truthful readiness reduction

Setup reduces readiness from the seam verdicts; it never upgrades one. `READY` requires every required seam in `## Required observations` to read `PRESENT` — including lane settlement, which reads `PRESENT` only from its owning probe's `PROVEN` verdict — and otherwise returns the not-ready verdict with exactly one attributable blocker per unproven prerequisite: the owning source, the observed evidence, and the smallest human action at that owner.

Setup names that boundary rather than crossing it. It does not create, install, bind, repair or re-derive a verdict another owner holds, and a not-ready verdict is the truthful report rather than a defect to repair inside setup. The selected Run's own entry re-reads its authority at its own boundary (ADR-0040's sole Start authority and the Domain action reducer), so aggregate setup health is orientation that never becomes a workflow gate.

## Result shape

Report one row per seam with its owning source, observed evidence, and state `PRESENT`, `MISSING`, or `UNKNOWN`. For every missing or unknown seam, name the smallest human action at that owner:

- install or select a delivery-substrate release that settles a mutation-capable managed-worktree lane, then re-read its lane record, before any lane is dispatched — readiness may claim `READY` only while this seam is `PRESENT`;
- provision the lane worker agent definition at the root the selected substrate declares, when that substrate's own read-back proves the lane's worker agent does not resolve there, using `agents/worker.md` as the canonical definition;
- finish the current repository configuration after the user approves the draft;
- reinstall or update the promoted skill set when a promoted surface is absent or mixed-version;
- install or update the separately authorized personal coordinator when its store or adapters are absent;
- for a missing GitLab Spec producer binding, name the installed coordinator's `references/gitlab-producer-adapters.md` and its separately authorized `configure` entry; for a missing Decomposition producer, name `references/gitlab-to-tickets-adapters.md` and distinguish a package update from the explicit consumer `Blocking representation` repair; re-running setup cannot create either adapter;
- repair tracker access or its repository configuration when the configured read cannot complete.

Preserve every repository file, tracker object, transaction, receipt, branch, worktree, writer lease, and remote ref during this diagnostic. Aggregate setup health is advisory context only: it is never cached as authority, never becomes a workflow gate, and never supplies a generic repair or force route.
