# Host cleanup recovery

Use this branch after the exact pending-directory removal fails or its tool rejects cleanup. Preserve the failed code/message and current Git/tracker observations. A policy rejection is `POLICY_REJECTED`, not an OS sharing error; stop at that boundary without alternate-tool retries.

The current Codex desktop bridge declares `CODEX_HOST_RELEASE_CAPABILITY` as `UNAVAILABLE`: it exposes no documented exact-task helper release, helper-ownership proof or respawn protection. Archive/handoff semantics and prior ad hoc PID stops do not establish such a capability. A new supported host contract and live Windows evidence are required before wiring a release operation. Never terminate arbitrary processes, patch the host or copy historical PIDs.

While the existing close owner holds both leases, call the read-only `assessPendingHostCleanup` from [pending-host-cleanup.mjs](../scripts/pending-host-cleanup.mjs) with `leases`, the unchanged completion, the original `taskRef`, a fresh native `readTask(taskRef)` returning its thread/turn snapshot, and the exact `failure: { code, message }`. It rechecks common directory, target cleanliness/ancestry, topic, unregistered ordinary empty path and exact idle task, then rechecks ownership after the native read. Unknown/running/foreign tasks, linked/nonempty paths and failed reads remain blockers. Idle metadata proves neither helper ownership nor respawn protection. The helper performs no filesystem, tracker or process mutation, including when a helper respawns during the read.

Release the target writer then repository close lease in the close owner's existing `finally` boundary. Read both leases back; retain any release failure alongside the original observation and preserve unresolved ownership. Do not roll back integration, invalidate completion, create an implementation-blocked note or replay verification.

For a coordinator invocation, return one native final-answer line `Workflow close result: <JSON>` with the helper result plus `schema: issue-close-result:v1`, `state: HOST_CLEANUP_BLOCKED`, exact accepted `runId`, `issueId`, `requestIdentity` and `authorityEvidence` from the close request. Retain `candidate`, `worktree`, `taskRef`, `directoryState`, `capability`, `reasonCode`, `observations` and actual lease read-back in the result. Never report closure while the directory remains. Direct invocation reports the same concrete blocker to its existing close owner.

Fresh source reconciliation binds the result to its native task/request, candidate, completion identity/body digest and worktree identity. It keeps completion valid and isolates only the affected Issue/dependents. An unchanged host blocker spends no continuation attempts; unrelated target movement does not resolve it. The same close owner resumes after supported host recovery yields new owning-source evidence, or physical absence permits the remaining tracker action. Linked, nonempty or contradictory state still stops through the existing ownership gate.
