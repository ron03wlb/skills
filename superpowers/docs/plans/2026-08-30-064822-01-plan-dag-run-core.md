# Deterministic DAG Run Core

**Goal:** Implement Issue #13's dependency-free runtime core for deterministic DAG Run reduction, durable control events, rebuildable status, and safe terminal-run retention.
**Why planning is required:** This is a public workflow contract with persistence, concurrency, and destructive cleanup semantics.
**Acceptance:** AC-1 through AC-5 pass through the public reducer and persistence interfaces; contradictions fail closed; cleanup is previewable, append-before-delete, and limited to proven eligible Runs; the candidate passes focused and repository verification plus Standards and Spec review.

### Outcome 1: Versioned deterministic reduction
- Work: Add a small normalized-fact interface and reducer under `skills/personal/run-issue-workflow/scripts/` that returns versioned Run state, node states, legal actions, frontier, and stable stop diagnoses without calling tracker, Git, Codex, HTTP, or rendering adapters.
- Risks/open questions: Cross-source contradiction, insufficient evidence, or malformed state must produce explicit fail-closed output rather than precedence or implicit repair.
- Verify: `node --test tests/ron-workflow/run-issue-workflow-core.test.mjs`

### Outcome 2: Bounded state and control semantics
- Work: Enforce the accepted Run and node transitions, default `max_parallel` of three, one close writer per target, three transient dispatch attempts, one remediation cycle per exact fingerprint, and revision-bound idempotent Pause, Resume, and Stop controls with no Start event.
- Risks/open questions: Control events may constrain reduction but must not overwrite authoritative node evidence or invent scheduling edges.
- Verify: `node --test tests/ron-workflow/run-issue-workflow-core.test.mjs`

### Outcome 3: Durable journal and rebuildable projection
- Work: Append only allowed control-engine events to `events.jsonl`, atomically replace `status.json` from journal plus current normalized evidence, rebuild after missing or corrupt snapshots, reject persisted token fields, and enforce one engine writer through an exclusive lock.
- Risks/open questions: Partial writes and replacement failures must preserve the previous durable state; status is never Resume authority.
- Verify: `node --test tests/ron-workflow/run-issue-workflow-core.test.mjs`

### Outcome 4: Auditable terminal-run retention
- Work: Provide cleanup preview and apply that retain every terminal Run from the last 30 days and at least the newest ten, skip non-terminal or uncertain/active Runs, append a cleanup record before deleting an eligible Run directory, and leave unrelated repository state untouched.
- Risks/open questions: Apply must stop deletion when cleanup-record append fails; tests may delete only isolated temporary fixture directories.
- Verify: `node --test tests/ron-workflow/run-issue-workflow-core.test.mjs`
