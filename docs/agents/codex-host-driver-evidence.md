The regression checks response equality, one native call, acknowledged delivery and no detached heartbeat after return. The 45 focused driver/bridge tests pass. This fixes the reproduced delayed-yield gap; the trigger of session `68633` remains unproven. Serialization and the 90-second idle-disconnect contract remain unchanged, so a host tool or execution isolate that stops servicing all pending work still requires original-owner reconciliation.

## Issue 85 bounded observation evidence

Issue 85 adds a bounded physical-write observation around the original writer, durable allowlisted identities and independent recovery budgets for concurrent transport/native faults, persisted 5/15/30-second read-only recovery rounds, and low-cost coordinator task observation. An unresolved or exhausted identity retains its consumed rounds across adapter re-entry. Exact settlement ends that fault episode, so a later distinct fault starts a fresh 5/15/30-second sequence. A rejected physical operation remains exhausted instead of opening a replacement writer; after exact stopped-cell evidence a restored pending owner is converted to read-only inspection state, and original-owner inspection can still settle an accepted response or prove that its saved native outcome is safe to redeliver. Lost settlement acknowledgement is reconciled by inspecting the exact request and consuming the bridge's payload-free accepted receipt without another settlement write. If the exhausted settlement never reached the bridge, that request and its fault remain fail-closed while later independent requests continue. The production composition binds this state to the exact Run ID. Event waits use 15-second slices, batches of at most eight exact task references, fair rotation and returned cursors. Control and optional execution-deadline signals are checked independently during event, lightweight snapshot and material full-history fault recovery. Unchanged running events do not trigger full task-history reads. When the active host lacks the otherwise allowed event tool, the driver returns its unsupported result under the original request ID so the adapter falls back to interruptible 15/30/60-second polling and lightweight output-free task snapshots; only a material terminal/anomalous observation requests bounded full history, and only a semantic task transition resets the interval. Buffered input also receives a bounded confirmation grace before an idle disconnect so concurrent Windows test load cannot convert an already-written heartbeat into host loss. Settled bridge requests retain a response digest for duplicate/conflict detection while discarding their accepted request payload. Bridge retention is capped at 1,024 settled receipts; the driver and durable checkpoint retain at most 100 recent settled requests.

Issue 87 binds every Issue execution phase to append-only `execution.started`, nondecreasing `execution.observed`, explicit `execution.uncertain`, and terminal `execution.exhausted` evidence. The cumulative limit is six hours across implementation, retries, material repairs, merge-conflict repair, and execution-owned verification/review. Native task observation is bounded by the smaller of 15 seconds and the proved remaining budget. Virtual boundary tests cover one millisecond before and exact exhaustion, restart without a monotonic anchor, native settlement, a recovery-owned repair interval, backward movement of both the monotonic execution clock and the wall-clock lease-health reader, a fresh settled fault episode, and preservation of independent Multi-Issue actions. Verified healthy repository/target-writer contention consumes no Issue budget and remains valid beyond twelve virtual hours. Partially failed health reads reuse the durable 5/15/30-second fault store, bind exact owner/generation identity, and never reinterpret `UNKNOWN` as inactive or as permission to release/reclaim.

## Issue 86 accepted-outcome reconciliation evidence

Issue 86 extends durable ownership from creation and close messages to retry, repair, recovery, model-upgrade, and recovery-ownership continuations. The Run/task receipt stores only the message kind, exact allowlisted operation-marker fields, prompt digest, acceptance source, task identity, and the consumed recovery-observation rounds. It stores no raw prompt. A reserved message is written before the native call; exact native response or task history records acceptance. The same allowlisted operation marker cannot acquire a different prompt digest, even after acceptance, and conflicting persisted ownership fails closed. An unresolved owner persists each 5/15/30-second observation before reading history, so adapter re-entry consumes only the remaining rounds and never opens another send. A transient history-read failure uses that already-recorded owner round and does not start a nested transport-recovery schedule. Restart, omitted native history, a lost acknowledgement, a different pending intent, or a non-allowlisted receipt field cannot authorize another send. Existing close-receipt records remain unchanged.

Mutation requests now carry allowlisted Run, Issue, task, operation-kind, and receipt-owner references through the bridge and payload-free driver checkpoint. Task creation and replacement/fork paths retain the same boundary. Browser controls also require a generated request ID and expected next Run revision, retain that pair in session storage across an uncertain request, and remove it only after a definite acceptance or rejection. `control.revised` records state-changing controls; `control.reconciled` binds a new identified idempotent request to its expected request revision without incrementing the current control revision or reopening cooperative settlement. A restored sending control performs only exact journal inspection. Matching ID, command, Run, and historical revision settles the original result even when later revisions exist; an absent or differently identified event remains unresolved, while mutation replay after a newer revision is stale. The three observations use the shared 5/15/30-second budget and never resubmit the control mutation. An identityless result cannot settle an identified pending control.

Deterministic fault-injection tests simulate accepted-before-recording, response loss, omitted history, adapter restart, same-operation prompt drift after acceptance, conflicting receipt content, restored control submission, matching historical journal read-back, stale control replay, identityless late control results, browser request identity, idempotent control settlement, model-upgrade continuation loss, recovery-handoff loss, persisted 5/15/30-second message observations across re-entry, and a combined lost acknowledgement plus history-transport failure. They also assert that raw prompts, native results, bridge credentials, and malformed payload details do not enter durable checkpoints or receipts. These fixtures do not claim provider exactly-once delivery or a live native interruption.

Conflict-recovery regressions combine those receipts with Issue 87 timing: fresh acceptance and same-invocation lost-ACK read-back retain the current execution start, while accepted or reserved receipts reconciled after restart remain historical observations. Receipt-backed terminal-history faults also yield at the remaining Issue observation budget without a nested retry or repeated native message.
