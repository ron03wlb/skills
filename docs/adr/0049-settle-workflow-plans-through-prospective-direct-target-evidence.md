# Settle workflow plans through prospective direct target evidence

This decision remains authoritative only for frozen legacy and producer-profile-v1 checkpoint resume. Fresh current-profile `to-spec` and `to-tickets` operations follow their purpose-specific producer transactions: they publish tracker authority and durable handoffs without a target operational-plan file, checkpoint commit, or prospective Direct target contribution. Existing valid incomplete legacy/profile-v1 operations retain the exact behavior below and are never rewritten as current-profile receipts.

An explicit human invocation of `to-spec` or `to-tickets` may prospectively authorize one **Direct target contribution** only for the exact **Workflow plan checkpoint** that the same operation requires and produces. Accepted glossary and ADR changes from `grill-with-docs` instead use one explicit **Planning artifact handoff** to `to-spec` and remain owned by its separate **Planning Seal**; scratch output, unaccepted drafts and unrelated work receive neither path. A new checkpoint operation starts only from an exact clean target after any valid Planning artifact handoff is sealed; any unrelated staged, unstaged, or untracked work is preserved but stops the operation before plan, Git, or tracker mutation, while a separately proved retry may recover only its own prior checkpoint state. Before writing the plan, the producer records one **Workflow checkpoint transaction** in the Git common directory that binds its Spec, target baseline, initially clean state, exact path and generated content. Reinvoking the same producer command automatically resumes an exact match at its first unsatisfied commit, attestation, publication, or handoff stage without regenerating the plan, duplicating a commit, or requiring another confirmation; any identity, baseline, path, content, commit, or tracker mismatch stops and preserves the transaction. An active or incomplete transaction blocks conflicting progress, while `handoff.completed` makes it a retained immutable receipt that downstream consumers may reread without a consumed-state mutation or automatic cleanup. `to-tickets` first consumes the completed `to-spec` handoff, then obtains exact `direct_target_contribution:v1` read-back before any decomposition publication mutation. A primary `to-spec` first creates the tracker identity required to own the record, then obtains read-back before completing body or label publication; revision mode records it before updating the existing Spec. Both producers automatically invoke model-invoked `attest-target-contribution` with the exact prospective packet; it is the only v1 writer, performs common eligibility, reuse, conflict and read-back validation, and returns the immutable record identity without creating the commit or resuming the producer. After exact publication read-back, `to-spec` appends `handoff.completed` with its immutable record identity. A Single-Issue Run consumes that handoff directly. For Multi-Issue, `to-tickets` appends one final `handoff.completed` that binds the consumed `to-spec` identity, its own immutable record identity and the valid decomposition record; Run consumes only this final handoff. These compact events support downstream start-readiness only and never substitute for tracker authority. Prospective creation reuses the unchanged v1 schema because it grants the same exact owner, target, commit and target-range coverage semantics as confirmation-gated recovery; only the pre-write authority and provenance checks differ. One owner may accumulate later v1 records for distinct checkpoints only when their commit sets are disjoint; an exact record is reused, while duplicate commits, partial overlap or conflicting purpose stops. Any drift, modification, ambiguity, mixed commit, evidence failure or multiple active transaction stops. This narrow producer path avoids a second confirmation and a new coverage schema while preserving confirmation-gated recovery for every other Direct target contribution and forbidding downstream workflows such as `run-issue-workflow` from repairing producer dirt.
