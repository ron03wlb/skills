# Run Tracker Specs as Codex-native DAGs

`/run-issue-workflow <Spec-ID>` is the sole Start authority for one bounded **DAG Run** over an exact **Tracker Spec** and **Issue target branch**. A Single-Issue Spec is a one-node DAG and `to-spec` routes it directly to this command. A Multi-Issue Spec first routes through `to-tickets` for one matching read-back **Decomposition publication record**, whose published blocker edges alone determine the ready frontier, then `to-tickets` routes the parent to this command without asking the human to execute individual children. Invocation reconciles tracker, completion-note, Git, worktree, Codex task, and run-journal evidence, creates or renews one exact **DAG Run Grant**, opens the Codex panel, and immediately executes without a second Start confirmation. No-argument `/run-issue-workflow` resumes only one unique non-terminal Run; zero candidates require a Spec ID and multiple candidates require explicit selection, so it never guesses a new Spec from the global `ready-for-agent` set.

Entry requires one minimal deterministic **Run-ready handoff** from the immediate upstream producer. For a fresh Single-Issue Spec, Run consumes only `to-spec`'s publication and `handoff.completed`. For a fresh Multi-Issue Spec, `to-tickets` first consumes the exact `to-spec` publication and handoff, then emits one final `handoff.completed` that binds those upstream identities, its operation receipt, and the existing valid decomposition record identity, digest, mapping, and blocker edges. Frozen legacy/profile-v1 handoffs keep their historical contribution-record identities. Run consumes only the immediate upstream handoff and never coordinates two producer transactions. It reuses existing target and tracker reads to require a clean target and no active or incomplete matching checkpoint transaction; completed transactions remain immutable receipts and do not block. Scripts and adapters normalize only `READY`, `INCOMPLETE`, or `UNKNOWN` plus compact evidence for the reducer. Run Entry never repeats producer generation, generated-content hashes, whole-commit eligibility, Direct target record validation, review, aggregate coverage, or producer recovery; those remain owned by the producer, `attest-target-contribution`, and `verify-target-before-push`. `INCOMPLETE` stops before dispatch and reports the exact `to-spec` or `to-tickets` command whose exact retry owns continuation; `UNKNOWN` stops with a structured upstream-handoff diagnosis.

The v1 coordinator is the active Codex task, not Orca or a Codex App Server client. It creates one sidebar-visible **Codex Issue lane** per executable Issue in the saved project's local environment. `execute-issue` remains responsible for creating or reusing that lane's dedicated **Issue worktree**, and every product edit, verification, review repair, and candidate commit occurs there rather than in the shared checkout. Dependency-ready lanes execute in parallel up to the Run Grant's `max_parallel`, defaulting to three; path, symbol, or module overlap may warn but never invents a blocker edge. A transient worker or terminal failure permits at most three dispatch attempts, reusing the same child task when reachable and journal-binding any proven replacement. Semantic or evidence failures do not consume that budget. One exact, reversible process-local remediation may run for a recognized environment fingerprint; on Windows, `gradle-loopback-safe` applies only to the exact `Selector.open()` loopback failure and preserves the rerun command's real result.

After a lane publishes valid `implementation_complete`, the coordinator sends one evidence-bound request into the existing idempotent `close-issue` path. That real close leaf alone acquires the repository close lease and then the target mutation writer, merges the unchanged reviewed candidate, removes the exact clean Issue worktree, closes and reads back the Issue, and releases both leases after settlement. The coordinator observes lease availability but never acquires, releases, reclaims, or delegates either lease. Repository-close or compatible target-writer contention enters a bounded evidence-preserving wait only after currently legal Issue dispatch, outside `max_parallel` execution slots and retry budgets. Only complete **DAG node success** releases outgoing edges. A failed child blocks its descendants while independent branches continue. When every child succeeds, the same Run Grant invokes one evidence-bound parent-only real close leaf, revalidates the decomposition and child reachability, and closes the main Issue. Run-level `SUCCEEDED` ends at that **DAG delivery success**; aggregate `/verify-target-before-push`, push readiness, push, and deployment remain separate and unauthorized.

The Codex panel is a replaceable status and control projection. It shows the DAG, child task state, close progress, exact failure evidence, attempted remediation and retries, affected and unaffected nodes, next owner, and Resume predicates. Its only controls are idempotent Pause, Resume, Stop, and read-only Refresh through a random-token-protected loopback bridge. Pause starts no new dispatch or closeout and lets active children settle; Stop revokes the Grant and performs no destructive cleanup. Closing the panel changes nothing. Automatic work exists only while the coordinator task is active; coordinator or app execution loss is fail-closed, settled child evidence is preserved, and a later explicit invocation reconciles without duplicate dispatch. Tracker unavailability similarly forbids cached authorization, makes three health/read probes after 5, 15, and 30 seconds without consuming Issue retry budget, and then records `tracker_unavailable` if evidence remains unavailable.

Each Run has one append-only `${git-common-dir}/matt-workflow-control/runs/<run-id>/events.jsonl` containing only control-engine-owned grants, control revisions, dispatch references, remediation records, repository-close or target-writer wait starts and settlements with exact pre-wait evidence and post-reconciliation outcomes, and pause or stop transitions. A versioned, atomically replaced `status.json` is a disposable panel projection; tracker, Git, worktree, and Codex task facts remain owned by their live sources, contradictions pause instead of using last-write-wins, and the per-run control token is never persisted. Explicit workflow invocation also performs a retention sweep: only `SUCCEEDED` or `STOPPED` Runs older than 30 days and outside the newest ten terminal Runs are eligible, uncertain engine-lock or active-task evidence skips deletion, and each removal is first recorded in append-only `cleanup.jsonl`; `--cleanup-preview` is read-only.

Every blocked, failed, or paused outcome carries one stable **DAG stop diagnosis** and **Workflow limitation class**. Instance problems may be corrected and resumed through full reconciliation. A control-engine defect or shared-skill contract gap is repaired in a separate scoped, reviewed, and verified task; a product Run never edits or installs its own governing workflow. This decision preserves ADR-0036's decomposition identities, ADR-0037's parent-only close contract, and ADR-0038's leaf execution, closeout, and push-verification boundaries, while superseding ADR-0038's assumption that a human must invoke and serialize every child closeout manually.
