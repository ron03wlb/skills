# Make setup an approved operational bootstrap

`/setup-matt-pocock-skills` is the single user-facing bootstrap for making the selected engineering workflow operational in one repository, not only a repository-markdown configurator followed by read-only missing-capability diagnostics. This direction is human-confirmed by the 2026-09-11 `/grill-with-docs` decision after the current setup contract reported a missing concrete GitLab `to-tickets@v2` adapter that it was forbidden to install or bind.

Setup first resolves the exact repository, required workflow surfaces, trusted committed source, immutable package, managed public entries, repository bindings, owning actions, effects, recovery evidence, and read-back checks. It presents that bounded plan once and performs the approved actions only after one explicit human acceptance. Installation, binding, tracker operations, and other effects continue to run through their existing non-overlapping owners; setup orchestrates them and verifies their receipts rather than reimplementing their mutation logic. This preserves ADR-0059 while removing the circular recovery in which downstream skills direct the human to setup and setup can only direct the human to another repair procedure.

Setup never silently selects an arbitrary latest revision, packages uncommitted work, broadens the accepted action set, overwrites unknown installation state, or treats diagnostics as mutation authority. If no trusted commit contains every required concrete surface, it stops before installation with `PRODUCT_CAPABILITY_MISSING`, identifies the missing owner and release requirement, and does not ask for a commit that cannot satisfy the capability. A retry reuses exact owner evidence and performs no mutation for already verified state. Changing an approved source, target, binding, external effect, or recovery action requires a new explicit decision for that changed plan.

The same approved plan includes create-only provisioning for exact missing tracker labels declared by the repository configuration and required selected workflow surfaces. This extension is human-confirmed by the subsequent 2026-09-11 decision and addresses the still-open upstream label-creation gap without moving label ownership into downstream producers. Setup lists every missing name before approval, leaves existing labels and their metadata unchanged, never renames or deletes a label, reads every accepted creation back, and resumes a partial result by creating only names still missing. Missing permission or contradictory provider evidence stops with the exact tracker owner and preserves successful creations; it never claims aggregate readiness or rolls back by deleting external state.

The accepted scope partition keeps concrete producer implementation, blocker representation, package installation mechanics, workflow repair, and release qualification with their existing owners. The bootstrap consumes those owner interfaces and receipts; it does not duplicate GitLab `to-tickets@v2` adapter work, ADR-0065 and Issue #50 blocker semantics, Issue #65 installation behavior, or Issues #88 through #91 recovery and qualification work. Upstream mattpocock/skills Issue #616 supplies the label-creation failure scenario, but its diverged community patch is not adopted as implementation authority because its forced upsert can modify existing label metadata and lacks this decision's exact pre-read, create-only, partial-result, and read-back boundaries. This non-overlap partition is human-confirmed by the 2026-09-11 Issue/WIP audit.

This ADR records the bootstrap architecture but grants no installation, tracker mutation, commit, publication, push, or deployment authority by itself. Existing installations remain valid; their next explicit setup invocation uses the new preflight and approval contract rather than being migrated in the background.
