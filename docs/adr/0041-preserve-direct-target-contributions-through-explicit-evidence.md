# Preserve direct target contributions through explicit evidence

Material target-branch commits outside every Issue contribution, referenced Planning Seal, and necessary merge topology may remain in history and enter target verification only as a **Direct target contribution** backed by an append-only read-back `direct_target_contribution:v1` comment on the exact owning Tracker Spec or Issue. Eligibility is limited to explicit human-directed, non-product workflow or governance maintenance outside an Executable Issue by design; active behavior, source, tests, configuration, dependencies, migrations, security, data, public APIs, and every mixed commit are ineligible and return to normal Issue delivery without partial-path attestation. The tracker record binds explicit human authority, scope, target, and commit identity but never claims historical review, verification, or push readiness; Git owns ancestry and the later aggregate gate proves quality. Recovery is triggered only when a frozen-range coverage check reports uncovered material commits and every proposed commit is eligible; matching records are reused, while review, test, cleanliness, ref, tracker, normal execution, and closeout failures never trigger it. The active workflow prepares the exact draft and asks for one human confirmation; only then may a separate model-invoked attestation helper write and read back the record, after which the workflow automatically starts a fresh verification from Entry rather than continuing the failed gate. We chose this over rewriting descendant Issue history, editing historical completion notes, per-SHA allowlists, verifier-created exceptions, silent or proactive attestation, local Git notes that do not travel by default, repository records whose own commits create a coverage loop, and reconstructed test claims.
