0. Guard 自動 action / impact / risk 分級 授權、範圍、acceptance、需要的 gates 不可跳過；read-only 也要分類，但不增加流程

4. Slice to-tickets vertical slices、blocking edges、approved granularity 一個 session 可完成

Authority 與 proof-state 速記

東西 它證明什麼 它不證明什麼
Wiki 已審核的現況業務知識基線 本 Issue 想改什麼
Matt spec 本 Issue 的 change contract 程式已正確完成
Code / tests 實作與驗證 evidence 現存行為必然是正確 business truth
Review pass 固定 diff 對指定 axes 的審查結果 已 merge、已 close、已部署
Commit 變更已形成 Git snapshot 已進 target branch 或 remote
Merge + target verification 目標分支含變更且指定 checks 通過 remote / runtime 已更新
Push / deployment evidence remote history / live runtime 的個別狀態 彼此不能互相替代

整合時的六條硬規則

  1. 一個 responsibility 只准有一個 owner。
  2. 自動 router 管風險；人工 router 管工作意圖，兩者不互相取代。
  3. Matt spec 是唯一 change contract；高風險 plan 只能引用它。
  4. 同類 TDD、debug、outgoing review 各合併成一份，不保留兩套並列觸發。
  5. Review、commit、merge、push、deployment 是不同 proof state。
  6. Child 不更新 Wiki；Parent / Standalone 在完整 Issue 收尾時 reconciliation。
